Technical specifications for native PostgreSQL schemas, star-schema dimension/fact tables, and ERD relational mapping.

Source-to-Target Pipeline Workflow

The platform operates on a native local PostgreSQL database engine (nonprofit_dw). Raw operational feeds land in staging schemas prior to execution through Node.js transactional logic and normalization into core star-schema tables.

Step 1
Raw Ingestion
Ingests raw payloads into stg_raw_donors_giving and stg_raw_resource_distribution schemas without altering raw types.
Step 2
Node.js ELT Validation
Backend pg client enforces UUID mapping, trims whitespace, and hashes credentials with bcryptjs (10 salt rounds).
Step 3
Analytics Warehouse
Normalized star-schema tables (fact_donations, fact_volunteer_activity) join tenant organizations for rapid indexed querying.

Production DDL & Composite Indexes

DDL definitions from schema.sql creating the multi-tenant relational star schema and performance indexes:

-- Indexes for Fast Analytics Querying
CREATE INDEX idx_donations_org_date ON fact_donations(org_id, transaction_date);
CREATE INDEX idx_volunteer_org_hub ON fact_volunteer_activity(org_id, hub_id);

-- Fact Donations Table DDL
CREATE TABLE IF NOT EXISTS fact_donations (
    donation_id VARCHAR(36) PRIMARY KEY,
    org_id VARCHAR(36) NOT NULL,
    donor_id VARCHAR(36) NOT NULL,
    payment_method VARCHAR(50) NOT NULL,
    amount DECIMAL(12, 2) NOT NULL,
    transaction_date DATE NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (org_id) REFERENCES organizations(org_id) ON DELETE CASCADE,
    FOREIGN KEY (donor_id) REFERENCES dim_donors(donor_id)
);
